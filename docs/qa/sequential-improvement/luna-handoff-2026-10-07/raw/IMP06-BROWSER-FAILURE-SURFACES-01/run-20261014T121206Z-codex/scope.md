# 현재 트리 브라우저 실패 표시 검증

ROOT 최신 Python/React 소스와 기존 사용자 frontend 변경38개를 읽고, 별도 소유 bundle로 타입검사·빌드한다. 제품 파일과 기존 bundle은 덮지 않는다. 현재 트리 fingerprint와 buildId를 고정하며 이를 clean 후보의 전체 승인으로 부르지 않는다.

실제 PIN UI 로그인, 실제 제품 chat SSE의 제어 provider 오류, 실제 제출된 queue task의 failed terminal을 관찰한다. provider 응답은 소유 loopback 실패 fixture이고 UI/API 응답을 page.route로 대체하지 않는다. 실제 모델 추론·다운로드0. 인증/제품 route/manager/runtime 연결을 유지한다. static mount의 bundle 위치만 새 소유 artifact를 가리키게 한다. 로그인·오류·회복 가능한 입력·실패 task 표시를 각각 현재 소스의 실제 브라우저에서 캡처하고 API/전송 근거를 연결한다. 전체 웹사이트 디자인·모델 품질·GA로 일반화하지 않는다. desktop1280x900 및 mobile460x900의 지정 화면 상태를 확인한다. 소유 server/browser/fixture 프로세스를 제한시간 안에 종료·회수한다.
