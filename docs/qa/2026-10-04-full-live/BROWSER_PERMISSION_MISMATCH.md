사용자가 제공한 설정 화면과 브라우저 도구의 응답이 일치하지 않는다. 원인은 미확정이며, 현재 SSAK-AI의 남은 실제 화면 검증은 재개되지 않았다.

## 관찰한 증거

- [사용자 제공 설정 화면](permission-setting-origin-allow.png)에는 정확한 `http://127.0.0.1:8000` 사이트별 행이 있다. 현재 보이는 **웹 검색**과 **다운로드** 열은 해당 사이트와 기본 행 모두 **항상 허용**이다.
- 이전 사용자 제공 화면에서 브라우저 사용 토글이 켜진 상태를 확인했다. 사용자는 오른쪽의 다른 권한 항목도 항상 허용으로 변경했다고 말했다. 해당 항목의 최종 화면은 이번 캡처에서 직접 확인되지 않았다.
- 사용자가 사이트별 허용으로 변경한 후 Root는 같은 선택된 내장 브라우저(`browser3`)에서 정확히 같은 origin에 `createBrowserTab`을 한 번 시도했다. 도구는 저장된 사용자 권한 설정이 `http://127.0.0.1:8000` 접근을 차단한다는 오류를 반환했다.
- 이 오류는 페이지 또는 SSAK-AI 서버를 검사하기 전에 발생했다. 따라서 이 시도는 서버 장애나 화면 내용의 성공·실패를 입증하지 않는다. 보이는 두 권한 열만으로 모든 권한 종류가 허용됐다고 단정하지 않는다.

## 확인한 경과와 경계

사용자는 기본 권한 변경, 사이트 권한 초기화, 모든 사이트 초기화, 앱 재시작을 진행했다고 알렸고, 마지막에는 해당 origin의 개별 허용 설정이 보이는 캡처를 제공했다. 그 이후의 도구 접근도 차단됐다. 동일 초기화나 재시작을 다시 요구할 근거는 아직 없다.

현재 증거만으로 Codex 결함, 관리자 정책, 캐시 또는 특정 설정 항목을 원인으로 확정하지 않는다. 다른 브라우저·호스트 별칭·CDP·HTTP로 이 권한 차단을 우회하지 않았으며, 외부 버그 게시도 수행하지 않았다.

## 검증 재개 조건

1. 같은 내장 브라우저에서 정확한 `http://127.0.0.1:8000`에 대한 도구 접근이 저장된 권한 오류 없이 성공해야 한다.
2. 해당 페이지의 최신 접근성 상태(`getAX`) 또는 실제 화면을 읽어 SSAK-AI가 열렸음을 관찰해야 한다. 설정 캡처나 탭 생성 성공만으로 남은 검증을 완료 처리하지 않는다.
3. 이후 [체크리스트](CHECKLIST.md)의 남은 질문·모델 화면·기능·시각 검증을 각각 실행하고 결과를 기록한다. 기존 미검증 항목과 리뷰 판정은 이 권한 설정 변경만으로 바꾸지 않는다.

전체 검증 범위와 미완료 조건은 [결과 요약](RESULTS.md)에 보존한다. 이 문서는 권한 불일치 증거만 기록하며 코드 수정, 사용자 권한 저장소 조회·변경 또는 추가 실행을 수행하지 않았다.
