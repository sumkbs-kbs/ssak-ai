## 기준과 책임

현재 공유 작업 폴더의 최신 코드를 기준으로 한다. 기존 헌법·Brain/Body·인증·
사용자 데이터와 모델 선택 정책을 유지한다. Root가 실제 실행 화면에서 직접
질문하고 실제 답변을 판정한다. 에이전트는 기능 조사·격리된 재현·수정·독립 검토를
분담하며 다른 작업자의 변경을 되돌리지 않는다. 과거 시험 통과를 이번 실사용
통과로 승계하지 않는다.

앱 결함·모델 응답 한계·설치/연결 부재를 구분한다. 발견한 앱 결함은 실패 시험→
최소 수정→같은 실제 시나리오 재검증 순서로 닫는다. 설치되지 않은 backend나
실제 자격증명이 필요한 연동을 허위 성공 처리하지 않는다. 사용자 자료를 대신
읽거나 삭제하지 않고 합성 QA 자료와 전용 대화를 사용한다.

## 기능별 검증 순서

1. 일반 코어 대화: 지시·계산·불확실성·문맥 정정·출력 형식·취소·이력.
2. 도구: 파일 읽기·오류·읽기 전용·웹 검색·출처·코드 실행.
3. 별도 cognitive surface와 메모리·근거·RAG·wiki.
4. 작업 실행·승인·분기·압축·프로젝트·파일 탐색·Git.
5. 모델·스튜디오·음성·스킬·플러그인·MCP·자료 추출·설정.
6. 데이터/금융/확률 평가 등 추가 API·CLI와 학습/승격의 권한 경계.

정확한 기능별 항목은 조사 결과에 따라 보완한다. 실행 및 개선 근거 디렉터리는
`docs/qa/2026-10-04-full-live/`다. 기존 완료 문서는 이 회차의 결과로 덮어쓰지 않는다.

실제 전체 기능군과 안전한 시나리오는
[INVENTORY.md](../qa/2026-10-04-full-live/INVENTORY.md)에 기록한다. 학습·설치·
원격 공개·외부 메시지·사용자 메모리 삭제를 실사용 검증이라는 이유로 실행하지 않는다.
그런 기능의 상태 조회와 합성 격리 실행을 실제 운영 연동과 구분한다.

## 최종 후보와 이어서 진행할 조건

Full HEAD는 `8cc94cf51952e3bbb6cb3f627683ca6c9c2d0382`, 소스 결속 manifest는
`c123fe7d90b4b8a03a98d1d33ff3a36487c6238d092bd3bcaa431a75242681a5`다.
공유 작업 폴더의 다른 변경은 이 회차 검증 대상으로 승계하지 않는다.
독립 검토는 4 PASS·context 1 FAIL로 전체 gate는 **FAILED**, visual은 모두
**REVISE / NEEDS EVIDENCE**다. 미달 조건을 문서 갱신만으로 PASS로 바꾸지 않는다.

사용자가 Codex 설정의 Browser에서 해당 사이트의 차단 기록을 삭제하면 접근 요청을
다시 받을 수 있다. 원래 `http://127.0.0.1:8000/chat` 탭에서 접근이 실제 복구된 뒤,
재시작한 서버의 READ_ONLY를 다시 확인하고 R2-12의 동일 질문을 재실행한다.
실제 검색 receipt·공식 링크의 클릭 가능한 렌더링·표를 함께 확인한다. 이어서
R2-17·모델 상태 UI·남은 로컬 기능 및 6개 누락 responsive frame·palette/modal을
검증하고 새 증거로 해당 gate를 다시 검토한다. 차단 우회는 하지 않는다.

최종 결과와 검토 집계는 QA 디렉터리의 RESULTS.md·REVIEW_SUMMARY.md,
실행 정리와 증거 경계는 RUNTIME_AUDIT.md에 기록한다. 당시 본 서버 PID25430은
유지했고 합성 UI QA 서버 PID30256과 임시 요청 header/저장소는 종료·제거를 확인했다.

## PIN 확인 후속 점검

사용자 요청에 따라 기존 인증 상태를 읽기 전용으로 확인했으며 저장된 PIN과
사용자 확인값의 일치 여부를 검증했다. PIN은 변경·초기화하지 않는다. 이 후속 점검 시점에는
과거 PID25430과 8000 리스너가 없었고, 기존 설정으로 실행을 복원한 새 서버는
PID58771에서 loopback 8000을 LISTEN한다. 로그인·실제 대화 성공 증거와 구분한다.

연결 실패까지 잘못된 PIN이라고 표시하는 오류는 최소 수정과 회귀 검증을 완료했다.
관련 23개 red→green, 격리 UI 회귀 1,219개, typecheck·build와 독립 scoped 코드
검토가 통과했다. 실제 로그인 화면과 브라우저 E2E는 접근 차단으로 미검증이다.
개인 인증 검증 자료는 공개 대상에서 제외하여 로컬에 보관한다.
기존 frozen manifest와 검토 판정은 과거 후보에 결속하며 후속 변경에 승계하지 않는다.
